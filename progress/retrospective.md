# Project Retrospective

## Project Window
📅 February 1, 2026 → February 28, 2026

## Original Intent
This project was meant to build an application that would be able to validate Sudoku puzzles based on rules applied.

## Timeline Summary
### Week 1 - Project Foundation
The project repository and application structure were created. A Blazor application was initialized and a database was configured to store Sudoku grid data and rules. Initial pages were created to begin supporting the UI.

### Week 2 - Sudoku Grid UI
The Sudoku page and grid layout were developed. A 9×9 grid with visible 3×3 box constraints was implemented, and puzzle data was loaded from the database. Basic cell selection functionality was also introduced.

### Week 3 - Interactions and Input
The grid interaction system was completed. Cell selection, keyboard navigation (WASD and arrow keys), and number input for both values and pencilmarks were implemented. By the end of this week the Sudoku board was fully interactive.

### Week 4 - Sudoku Validation
The focus of this week was planned to be implementing the Sudoku validation logic for rows, columns, and 3×3 box constraints.

No development work was completed during this week, so the validation logic originally planned for the project was not implemented.

## Key Learnings
### Blazor Project Setup
Learned basic Blazor project structure, configuration of the application, organization the initial pages, and database integration needed to support the Sudoku grid.

### Blazor Page Layout
Explored how Blazor pages can be structured to render dynamic content, including building the main Sudoku page and rendering a grid-based layout.  Explored how Blazor and HTML/Javasscript interact together to make the pages dynamic.

### Blazor Child Component Patterns
Gained experience designing reusable UI components by separating parts of the Sudoku grid into smaller components and managing interactions between them.  

### CSS Layout and Design
Improved understanding of CSS grid layout and styling techniques required to visually represent the 9×9 Sudoku board and its 3×3 box constraints.

## What I'd Change Next Time
### Initial Project Design
Create a full plan with weekly goals and areas of focus for the project before starting.

### Project Setup
Consider which would be better: having the project setup as part of the project or having it done before starting.

### Timeboxing
Consider timeboxing working hours more.  Limit the daily project work to 1-2 hours instead of working until reaching a good stopping point.

### Daily/Weekly Logs
Be more proactive in updating the project logs to make sure that the projects remains up to date with these logs.

### Documentation
Add more documentation around each piece of code to describe how it works and the reason behind implementation.

### AI Usage
Reduce the amount of AI assistance used for parts of the project like logs or implementation in order to improve problem-solving and critical thinking skills.
